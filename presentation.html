01 · Problem

โจทย์ไม่ได้อยู่ที่ “ไม่มีระบบ”
แต่อยู่ที่ ข้อมูลไม่ช่วยตัดสินใจ

01

บันทึกซ้ำ

ข้อมูลเดียวกันถูกป้อนหลายจุด ทำให้ workflow ขาดความต่อเนื่อง

02

ข้อมูลกระจัดกระจาย

การประเมิน ความเสี่ยง และ nursing note แยกออกจากกัน

03

เห็นช้า → ตอบช้า

ผู้ปฏิบัติต้องค้นข้อมูลและแนวทางด้วยตนเองจากหลายแหล่ง

Insight: การทำให้ “ไร้กระดาษ” เพียงอย่างเดียว ไม่ได้ทำให้การตัดสินใจทางคลินิกดีขึ้นโดยอัตโนมัติ

03 · System architecture

โครงสร้าง 3 ชั้นที่เชื่อม “ข้อมูล” กับ “การตัดสินใจ”

ตั้งใจแยกบทบาทของหน้าจอ ข้อมูล และ intelligence เพื่อให้ระบบขยายต่อได้โดยไม่ทำลาย workflow หลัก

Presentation layer

Dashboard และ module UI สำหรับงานเวร ให้ผู้ใช้เห็น context ของผู้ป่วยและสิ่งที่ต้องทำต่อ

Patient list · risk badges · note forms · handoff
→

Clinical record layer

ข้อมูลผู้ป่วยและเวชระเบียนถูกรวมให้เชื่อมต่อกัน ลดการบันทึกซ้ำจากกระดาษ

Assessment · Focus · Progress · Education
→

Decision support layer

CANDI Assistant และ rule-based alerts ช่วยสรุป ชี้ประเด็น และพาไปยังแนวทางที่เกี่ยวข้อง

Risk alerts · guideline hub · AI-assisted drafting
หลักการกำกับ: AI ช่วย “เตรียมข้อมูลและร่างข้อความ” แต่การประเมินความเหมาะสมและการตัดสินใจทางคลินิกยังอยู่ที่พยาบาล

07 · Safety & data governance

ความฉลาดของระบบ ต้องมาพร้อม “ขอบเขตของระบบ”

01 · Context

De-identification

ก่อนส่ง context ไปยัง AI ระบบมีแนวคิดในการลดข้อมูลที่สามารถระบุตัวบุคคลได้

02 · Control

Human in the loop

AI ทำหน้าที่ช่วยร่างและชี้ประเด็น ไม่ใช่ผู้ให้การวินิจฉัยหรือสั่งการแทนพยาบาล

03 · Workflow

Patient context lock

เมื่อเปลี่ยนเคส ระบบล้างบริบทสนทนาเพื่อช่วยลดความเสี่ยงจาก context leakage

หลักกำกับของ CANDI: “ช่วยให้เห็นเร็วขึ้น — แต่ไม่ตัดสินใจแทนคน”เป็นแนวคิดเชิงออกแบบของระบบ ไม่ควรตีความว่าเป็นการรับรองความปลอดภัยในทุกบริบทการใช้งาน
