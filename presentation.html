CANDI · INV-T02
ผลงานการพัฒนาคุณภาพการบันทึกเวชระเบียนทางการพยาบาล

พัฒนาคุณภาพ
ก่อนพัฒนาเทคโนโลยี

การปรับปรุงคุณภาพการบันทึกเวชระเบียนทางการพยาบาลด้วยระบบสนับสนุนการตัดสินใจทางคลินิก โดยใช้ CANDI เป็น “เครื่องมือของ CQI” เพื่อแก้ปัญหาจากกระบวนการทำงานจริง

โรงพยาบาลสมเด็จพระยุพราชสว่างแดนดินพยาบาลวิชาชีพปฏิบัติการ
แก่นของผลงาน
“เปลี่ยนระบบบันทึก” → “เปลี่ยนกระบวนการดูแลข้อมูล”
CQI เป็นกรอบนำ · นวัตกรรมเป็นเครื่องมือ · ผลลัพธ์เป็นหลักฐาน
นายนัทธ์นรินทร คำนาโฮม01
01 · ปัญหาและความสำคัญ

ปัญหาหลักคือ “คุณภาพของข้อมูล” ไม่ใช่เพียง “รูปแบบกระดาษ”

A

อ่านข้อมูลยาก

การบันทึกด้วยลายมือมีข้อจำกัดต่อความชัดเจนและการสื่อสารข้อมูล

B

ข้อมูลกระจาย

Assessment, risk และ nursing note ไม่ได้เชื่อมอยู่ใน workflow เดียว

C

บันทึกซ้ำ

ผู้ปฏิบัติต้องถ่ายทอดข้อมูลเดิมหลายตำแหน่งในกระบวนการดูแล

D

ใช้ข้อมูลเพื่อ “บันทึก” มากกว่า “ตัดสินใจ”

แนวทางดูแลและสัญญาณความเสี่ยงไม่ได้อยู่ใกล้จุดตัดสินใจเสมอ

Baseline · ทบทวนคุณภาพเวชระเบียน
76.66%
ความอ่านได้ของลายมือ

ตัวชี้วัดตั้งต้นที่สะท้อนช่องว่างด้านคุณภาพการสื่อสารผ่านเวชระเบียนทางการพยาบาล

จุดเปลี่ยน: จากการแก้ปัญหา “เอกสาร” → มองทั้งระบบการรับข้อมูล–ประเมิน–ตัดสินใจ–บันทึก–ส่งต่อ

02 · วิเคราะห์สาเหตุ

เมื่อมองเป็นกระบวนการ ปัญหาไม่ได้เกิดจาก “คน” จุดเดียว

จึงวิเคราะห์ปัญหาในระดับ workflow และ information flow เพื่อหาจุดที่ควรปรับปรุง

Process
กระบวนการ
หลายขั้นตอนแยกส่วน ทำให้ข้อมูลไม่ต่อเนื่อง
→ รวม workflow ให้เป็นเส้นทางเดียว
Information
ข้อมูล
ข้อมูลสำคัญกระจายและต้องค้นหาหลายจุด
→ แสดง context เดียวกันในจุดใช้งาน
Decision
การตัดสินใจ
risk และแนวทางดูแลไม่ได้เชื่อมกันทันที
→ ฝัง alert และ guideline ใน workflow
Documentation
การบันทึก
โครงสร้าง note และการส่งต่อยังมีภาระการบันทึกซ้ำ
→ structured nursing record
ประเด็น CQI: ถ้าปรับเฉพาะหน้าจอ แต่ไม่ปรับกระบวนการ ปัญหาเดิมจะย้ายที่ ไม่ได้หายไป

03 · วัตถุประสงค์

เป้าหมายการพัฒนาคือ “คุณภาพการบันทึก” ที่สนับสนุนการดูแล

Objective 01
เพิ่มคุณภาพข้อมูล
ทำให้ข้อมูลการพยาบาลมีความชัดเจน เป็นโครงสร้าง และค้นใช้ได้ง่าย
Q
Objective 02
สนับสนุนการตัดสินใจ
เชื่อมการประเมินความเสี่ยงกับข้อมูลและแนวทางปฏิบัติที่เกี่ยวข้อง
D
Objective 03
ลดภาระงานที่ไม่จำเป็น
ลดการบันทึกซ้ำและลดเวลาที่ใช้ในการค้น/ตั้งต้นข้อมูล
T
ตัวชี้วัด CQI ต้องตอบ 3 คำถาม: คุณภาพดีขึ้นหรือไม่ · ใช้งานได้จริงหรือไม่ · ผู้ปฏิบัติใช้เวลาอย่างไร
CQI · Objectives04
04 · กลยุทธ์การปรับปรุง

ใช้วงจร CQI เป็นแกน และพัฒนาเทคโนโลยีเฉพาะจุดที่จำเป็น

01 · REVIEWทบทวนเวชระเบียนและ pain point จากการทำงานจริง
02 · ANALYZEวิเคราะห์จุดสะดุดของข้อมูลและกระบวนการ
03 · DESIGNออกแบบ workflow และเครื่องมือให้สอดคล้องงาน
04 · TESTทดลองใช้ รับข้อเสนอแนะ และติดตามการใช้จริง
05 · IMPROVEปรับระบบจากผลลัพธ์และ feedback แล้ววนซ้ำ
CQI principle
“นวัตกรรมเกิดขึ้นหลังจากเข้าใจปัญหา ไม่ใช่ก่อนวิเคราะห์ปัญหา”
จุดเน้นของผลงานจึงอยู่ที่กระบวนการพัฒนาและการเปลี่ยนแปลงคุณภาพ มากกว่าความใหม่ของเทคโนโลยีเพียงอย่างเดียว

05 · Intervention

การปรับปรุงไม่ได้มี “CANDI” อย่างเดียว แต่เป็นชุดการเปลี่ยนแปลง

Process

ปรับ workflow การบันทึก

เชื่อม Assessment → Focus → Progress Note → Education → Handoff

ลดขั้นตอนที่ซ้ำซ้อน · วางข้อมูลตามลำดับงาน
Standard

จัดโครงสร้างข้อมูล

ทำให้รูปแบบการบันทึกและข้อมูลสำคัญมีโครงสร้างเดียวกัน

Focus List · S-O-I-E · structured fields
Support

เพิ่ม decision support

แสดง risk alert, guideline และเครื่องมือช่วยร่างข้อมูลใกล้จุดตัดสินใจ

CANDI = เครื่องมือสนับสนุนการปรับปรุง
ก่อนข้อมูลแยกส่วน
→ 1รวมข้อมูลสำคัญ
→ 2เตือนความเสี่ยง
→ 3เชื่อม guideline
→ 4บันทึกเป็นโครงสร้าง
หลังข้อมูลพร้อมใช้ต่อเนื่อง

06 · Innovation as a CQI tool

แล้ว “นวัตกรรม” อยู่ตรงไหน?

อยู่ที่การแปลงปัญหาคุณภาพให้เป็นเครื่องมือที่ใช้ได้จริงใน workflow ของพยาบาล

01

Risk Alert

เห็นสัญญาณความเสี่ยงสำคัญในบริบทของผู้ป่วย

02

Structured Record

จัดข้อมูลการบันทึกให้ค้นและทบทวนได้ง่ายขึ้น

03

CANDI Assistant

ช่วยสรุปและตั้งต้นข้อความโดยมีพยาบาลตรวจสอบ

04

Copy-to-form

ลดการถ่ายทอดข้อความซ้ำระหว่างโมดูล

ภาพระบบจาก repository · ใช้เป็นหลักฐานประกอบการอธิบายนวัตกรรม ไม่ใช่ผลลัพธ์การศึกษา

CQI · Process change10
10 · การเรียนรู้และข้อจำกัด

CQI ที่ดีต้องพูดทั้ง “สิ่งที่ดีขึ้น” และ “สิ่งที่ยังต้องพิสูจน์”

Learning 01

Workflow มาก่อน Technology

เมื่อเข้าใจ pain point ของผู้ปฏิบัติ การออกแบบระบบจึงตอบโจทย์การใช้งานมากขึ้น

Learning 02

ข้อมูลต้องเชื่อมกัน

คุณค่าของระบบเกิดจากการเชื่อม assessment, risk และ documentation ไม่ใช่จาก feature รายตัว

Learning 03

ต้องวัด outcome ให้มากขึ้น

รอบต่อไปควรเพิ่ม objective time-on-task, documentation quality และผลลัพธ์ทางคลินิกที่เกี่ยวข้อง

ข้อจำกัดสำคัญ: ข้อมูลเวลาที่ลดลงเป็น self-reported/recall-based และความพึงพอใจเป็นตัวชี้วัดประสบการณ์ จึงไม่ควรสรุปเป็น causal effect โดยลำพัง

11 · ความยั่งยืน

จาก “โครงการ” สู่ “วงจรปรับปรุงคุณภาพประจำงาน”
